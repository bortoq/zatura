# Follow-up audit fixes for 11c5978, 2026-10-06

This report covers the new findings in
`zatura-audit-report-2026-10-06-11c5978.md`. The earlier report describes the
initial fix and its own environment; its 22-suite results are historical, not
independent evidence supplied by the second auditor.

## Changes

| Finding | Implementation |
| --- | --- |
| P1: ABI 6–7 without Landlock TSYNC | Production strict Landlock startup now refuses ABI <8 and unconditionally requests TSYNC on supported kernels. Failure is fatal; there is no unsynchronized fallback. Explicit Landlock setup also requires seccomp and adequate headers. |
| P2: inherited writable FD | Linux entry closes every inherited non-stdio FD before initialization. Writable filesystem stdio is redirected to `/dev/null`; pipes and recorded terminals remain available. After enforcement, startup rejects writable linked regular files and unexpected devices. Only kernel anon-inode handles and unlinked memory-backed buffers are exempted. |
| Writable metadata through read-only FD | Seccomp also denies `fchmod`/`fchmodat` and `mkdir`/`mkdirat`, including the former X11 allowances. Anonymous display-buffer `write`, `writev`, `ftruncate` and `fallocate` remain usable. |
| Coverage | Added real FD/write-family regressions, deterministic production ABI-boundary tests for 6/7/8+, and a real-kernel thread test. Added a manually dispatched ABI 8+ runner workflow whose required runtime gate rejects SKIP. Sandbox session tests now export the plugin API and can load real engines. |
| Misleading comments/docs | Corrected GTK/GLib versus document-renderer thread timing. README and SANDBOX.md distinguish normal native packages, combined sandbox and seccomp-only limitations. The startup message no longer promises an unconditional strict boundary. |

The PDF smoke parent now owns the log file and drains a pipe from the viewer;
it does not give the parser a writable log FD. Required-test failure diagnostics
show only test names/status/exit codes, not the logged process environment.
Existing local GPU changes were retained and are not part of these fixes.

## Remaining validation before release

The positive ABI 8+ TSYNC runtime test cannot run on this host. Use the
`Landlock ABI 8 runtime` manual workflow on a runner labelled `landlock-abi8`,
or run `LANDLOCK_REQUIRE_TSYNC=1 tools/test-native-sandbox.sh` on such a kernel.
The test starts a worker before enforcement and another after enforcement;
with seccomp absent, both must be denied filesystem writes by Landlock itself.
No such runner was registered or started as part of these changes.

These changes do not claim a formally proven read-only boundary for every IPC
or mapped-memory capability in the single-process architecture. X11 isolation
and trusted compositor IPC remain limitations documented in SANDBOX.md.

The ordinary native packages still disable both mechanisms by design. Their
previous PDF smoke results do not validate this sandbox. No new public release
is published here; use a new version/tag before publishing, and run the full
package/source-Flatpak and interactive portal verification described in
PACKAGING.md and SANDBOX.md.

Kernel policy semantics were checked against the
[Linux Landlock documentation](https://docs.kernel.org/userspace-api/landlock.html).
